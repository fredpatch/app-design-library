# Contributing

## Workflow

1. Document the recurring UI problem.
2. Identify at least two realistic consumers.
3. Define the public API before implementation.
4. Add semantic-token usage.
5. Add Storybook states and accessibility checks.
6. Validate under Prestix and ANAC themes.
7. Validate comfortable, compact, and dense modes.
8. Avoid direct business-domain imports.

## Naming

Use generic capability names such as `StatusBadge` or `EntityListPage`.
Do not use source-domain names such as `InvoiceStatusBadge`.
